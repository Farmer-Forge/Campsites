# OSM campgrounds are retired, never deleted

A campground that drops out of OpenStreetMap could simply be deleted, but `favorites`, `trip_stops`, `campground_attributes` and `campground_state_log` all reference `campgrounds(id)` with `on delete cascade`, so a delete would silently remove users' favorites and trip stops. So an OSM campground that's gone, no longer classed as state-run, or now a duplicate of an NPS/RIDB campground is **retired** (`retired_at`, `retired_reason`): search leaves it out, and favorites and trips still show it, marked "No longer listed". If it reappears it's unretired. A check limits retiring to `osm` rows, so NPS and RIDB rows keep their upsert-only behavior. Because one bad Overpass response (empty, or partial and accepted as complete) would retire a whole state, a run that fetched nothing or kept under half the state's last `ok` count retires nothing and is logged `guarded` (Shawn, 2026-11-26; `~/plans/2026-11-26-campsites-state-parks-osm-design.md` on Lisa).
